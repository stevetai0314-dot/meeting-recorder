# 錄音加入麥克風混音 — 設計文件

日期：2026-08-14
狀態：已與用戶確認

## 目的

現行 `recorder.html` 只透過 `getDisplayMedia` 錄「分頁／系統音訊」，錄不到使用者自己講話的聲音，只適合純聽對方發言的場景。改成系統音訊＋麥克風混音成一軌一起錄，讓外銷部同仁自己開口參與的會議也能完整收音。

## 已確認的決策

| 決策點 | 結論 |
|--------|------|
| 麥克風權限被拒/無裝置時的行為 | 不中止錄音，照常只錄系統音訊，並在狀態列提示 |
| 音量表 UI | 拆成「系統音訊」「麥克風」兩條獨立顯示 |
| 上傳／分析／MP3 轉檔邏輯 | 不變（吃的是混音後的單軌 webm，對它們透明） |

## 架構

```
startRecording()
  1. getDisplayMedia({video:true, audio:true}) 取系統音訊
     → 沒抓到音軌：照現行邏輯中止並警告（不變）
  2. 嘗試 getUserMedia({audio:true}) 取麥克風
     → 失敗（拒絕/無裝置）：不中止，micStream = null，
       狀態列提示「未取得麥克風權限，僅錄系統音訊」
  3. new AudioContext() → createMediaStreamDestination()
     → 系統音軌 connect 進 destination（一定有）
     → 麥克風音軌 connect 進 destination（如果有）
  4. MediaRecorder 改錄 destination.stream（取代現行的 audioOnlyStream）
  5. 系統音訊/麥克風各自另外 connect 一個 AnalyserNode，
     驅動兩條獨立音量表（沿用現行 updateLevel 的 RMS 計算方式，複製成兩份）

stopRecording()
  - 除了現行 stop tracks，新增停止麥克風 stream 的 tracks
  - audioCtx.close() 沿用不變（destination 屬於同一個 context，一併釋放）

其餘不變：
  - onRecordStop / encodeMp3 / uploadAndAnalyze / GAS 呼叫 — 完全不動
  - 畫面版面/上傳流程/結果顯示 — 不動
```

## UI 變更

- `<div id="level">` 區塊由單條改為兩條：
  - 「系統音訊」音量表（原本的 `#levelBar`，ID 不變，語意改為系統音訊專用）
  - 「麥克風」音量表（新增 `#micLevelBar`）
- 麥克風權限被拒時，麥克風音量表維持灰色 0%，不特別隱藏（讓使用者一看就知道沒收到）

## 錯誤處理

- 系統音訊抓不到：中止錄音並警告（現行行為不變）
- 麥克風抓不到：不中止，僅提示，繼續錄系統音訊（新行為，本次核心決策）
- 混音／AudioContext 建立失敗：視同現行「沒有可用音訊來源」的錯誤路徑，中止並警告

## 明確不做（YAGNI）

- 系統音訊與麥克風分開存成兩軌（雙軌檔）— 用途是通話收音，混一軌即可，跟現行輸出格式一致
- 麥克風裝置選擇下拉選單 — 目前場景單一麥克風，不需要
- 音量表以外的麥克風測試/校準功能

## 驗收標準

1. 正常情境：分享系統音訊＋允許麥克風權限 → 開始錄音 → 對著麥克風講話同時播放另一段聲音 → 兩條音量表都會跳動 → 停止錄音 → 下載/播放檔案，兩邊聲音都聽得到
2. 拒絕麥克風權限情境：分享系統音訊＋拒絕麥克風 → 狀態列出現「僅錄系統音訊」提示 → 錄音仍正常進行 → 錄出檔案只有系統音訊，功能與現行版本一致
3. 拒絕系統音訊分享情境：沿用現行行為，中止並警告
4. 上傳分析、MP3 轉檔、寫入 Sheet/Drive 全部不受影響，行為與現行版本相同
